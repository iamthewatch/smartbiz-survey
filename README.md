# SmartBiz Survey

Конструктор анкет для работы с лидами. Администратор собирает анкеты в визуальном конструкторе,
отправляет лидам персональные ссылки и смотрит аналитику по каждому лиду или по всем сразу.

| Слой     | Технологии |
|----------|------------|
| Backend  | Java 21, Spring Boot 3.5, Spring Security (JWT), Spring Data JPA, Liquibase, PostgreSQL 17 |
| Frontend | React 18, TypeScript, Vite, Tailwind CSS, Framer Motion, dnd-kit, Recharts |

## Быстрый старт (разработка)

```bash
# 1. База данных (PostgreSQL в Docker на порту 5434, только для локального запуска)
docker compose -f docker-compose.db.yml up -d

# 2. Backend — http://localhost:8080 (Swagger: /swagger-ui.html)
cd backend
mvn spring-boot:run

# 3. Frontend — http://localhost:5173 (запросы /api проксируются на :8080)
cd frontend
npm install
npm run dev
```

**Вход:** `admin` / `admin123`. Администратор создаётся Liquibase-миграцией
`backend/src/main/resources/db/changelog/changes/002-admin-user.yaml`. Регистрации нет.
Пароль меняется в разделе «Настройки».

## Запуск в Docker (сервер)

`docker-compose.yml` поднимает только backend и frontend. База внешняя — на сервере она уже есть,
её адрес и доступы передаются через переменные окружения (например, в файле `.env` рядом с compose-файлом):

```bash
DB_URL=jdbc:postgresql://<хост-базы>:5432/smartbiz_survey
DB_USERNAME=survey
DB_PASSWORD=<пароль>
JWT_SECRET=<длинный-случайный-секрет-от-32-символов>
CORS_ORIGINS=https://<ваш-домен>
FRONTEND_PORT=8095   # сайт (по умолчанию 8095)
BACKEND_PORT=8096    # API напрямую, Swagger (по умолчанию 8096)
```

```bash
docker compose up -d --build
```

Если какая-то из обязательных переменных не задана, compose остановится с подсказкой.
Если база стоит на том же сервере вне Docker, используйте хост `host.docker.internal`.

Сайт откроется на порту `FRONTEND_PORT` (8095): nginx внутри контейнера отдаёт фронтенд и проксирует `/api` на бэкенд.
Бэкенд напрямую доступен на `BACKEND_PORT` (8096), например Swagger: `/swagger-ui.html`.

Для полностью локального запуска в Docker сначала поднимите базу из `docker-compose.db.yml`, затем приложение с
`DB_URL=jdbc:postgresql://host.docker.internal:5434/smartbiz_survey`, `DB_USERNAME=survey`, `DB_PASSWORD=survey`.

## Возможности

**Конструктор анкет**
- 12 типов вопросов: один вариант, несколько вариантов, выпадающий список, короткий и развёрнутый текст,
  оценка звёздами, шкала / NPS, да/нет, число, дата, email, телефон
- Вариант «Другое» со своим ответом, ограничения «выбрать от N до M», диапазоны для чисел и шкал
- Порядок вопросов и вариантов меняется перетаскиванием, вопросы можно дублировать и менять им тип
- Enter добавляет новый вариант; вставленный список из нескольких строк превращается в несколько вариантов
- Изменения сохраняются автоматически. Конфликт правок из двух вкладок обнаруживается по версии анкеты
- Предпросмотр, цвет анкеты, приветствие и сообщение после отправки
- Шаблоны: квалификация лида, NPS, обратная связь
- Статусы: черновик → опубликована → закрыта. Перед публикацией анкета проверяется

**Рассылка**
- Персональная ссылка для каждого лида (`/i/{token}`). Повторно пройти анкету по ней нельзя
- Отправка в WhatsApp, Telegram или на email по редактируемому шаблону с `{имя}` и `{ссылка}`
- Воронка: приглашено → открыли → прошли
- Общая публичная ссылка (`/s/{slug}`): можно спрашивать контакты (респондент сохраняется как лид) или принимать анонимные ответы

**Прохождение анкеты**
- Пошаговый режим с прогрессом и анимациями или все вопросы на одной странице
- Горячие клавиши: A/B/C для вариантов, цифры для шкал, Enter — дальше
- Ошибки проверяются и на клиенте, и на сервере

**Аналитика**
- По всей анкете или по одному лиду
- Графики по каждому вопросу: распределение вариантов, средняя оценка, NPS, доли да/нет, текстовые ответы
- Динамика ответов за 30 дней, конверсия приглашений, среднее время прохождения
- Список ответов с подробным просмотром, экспорт в CSV (открывается в Excel)
- Карточка лида: все его приглашения и ответы

**Лиды**: поиск, добавление, редактирование, массовый импорт из Excel или CSV.

## Устойчивость бэкенда
- Liquibase управляет схемой, а Hibernate только проверяет её при старте (`ddl-auto: validate`)
- Анкета сохраняется одним запросом `PUT /api/surveys/{id}`. Вопросы и варианты сопоставляются по id: существующие
  обновляются, новые создаются, отсутствующие удаляются. Id остаются стабильными, поэтому собранные ответы не теряются
- Оптимистическая блокировка (`@Version`) защищает от одновременных правок
- Пессимистическая блокировка приглашения защищает от двойной отправки ответа
- Каждый ответ проверяется по структуре анкеты: обязательность, принадлежность варианта вопросу, диапазоны, форматы
- Защита от перебора пароля, единый формат ошибок `{status, code, message, details}`, защита CSV от инъекций формул

## Переменные окружения backend

| Переменная | По умолчанию |
|---|---|
| `DB_URL` | `jdbc:postgresql://localhost:5434/smartbiz_survey` |
| `DB_USERNAME` / `DB_PASSWORD` | `survey` / `survey` |
| `JWT_SECRET` | dev-секрет. **Обязательно задайте в продакшене** (≥ 32 символа) |
| `JWT_TTL_HOURS` | `12` |
| `CORS_ORIGINS` | `http://localhost:5173,http://localhost:3000` |
